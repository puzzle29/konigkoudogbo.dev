Laboratoire code (Python)

Exécuté localement dans le navigateur grâce à Pyodide : les temps mesurés sont ceux de ta machine. Le navigateur exécute Python plus lentement qu'une installation native, mais les rapports entre méthodes restent parlants.

Expérience 1

Additionner 1 million de nombres, trois façons

1. Objectif
Mesurer l'écart entre une boucle interprétée, une fonction native et un calcul vectorisé.
Résultat attendu
La boucle Python est la plus lente ; numpy est typiquement des dizaines à des centaines de fois plus rapide.

2-3. Code et exécution

Premier lancement : téléchargement de Python (Pyodide) et numpy, ~10-20 s.
4. Ce qu'il faut observer
Le nombre d'additions par seconde de chaque méthode.
5. Interprétation
Chaque tour de boucle Python exécute des dizaines d'instructions machine (vérifier les types, allouer des objets). numpy exécute une boucle compilée sur un tableau contigu en mémoire, avec des instructions SIMD qui additionnent plusieurs nombres à la fois.
6. Lien avec le HPC
Sur Jean Zay, aucun code de production ne fait la boucle en Python : le travail lourd est délégué à des bibliothèques compilées (BLAS, cuBLAS, PyTorch) qui exploitent SIMD, cœurs et GPU.

Expérience 2

Le cache : parcourir une matrice en lignes ou en colonnes

1. Objectif
Voir la localité spatiale de tes propres yeux.
Résultat attendu
Le parcours par colonnes est nettement plus lent (souvent 2 à 10 fois), alors que le nombre d'additions est identique.

2-3. Code et exécution

Premier lancement : téléchargement de Python (Pyodide) et numpy, ~10-20 s.
4. Ce qu'il faut observer
Le rapport entre les deux temps.
5. Interprétation
En ligne, chaque ligne de cache de 64 octets chargée contient 8 nombres utiles. En colonne, chaque accès saute de 16 000 octets : presque chaque lecture est un cache miss.
6. Lien avec le HPC
Les codes HPC organisent leurs données (« layout ») pour que les accès soient contigus — sur CPU pour le cache, sur GPU pour les accès « coalescés ».

Expérience 3

Multiplication de matrices : boucles vs BLAS

1. Objectif
Calculer des GFLOPS réels et comprendre pourquoi les bibliothèques optimisées comptent.
Résultat attendu
Les boucles plafonnent à une fraction de GFLOPS ; numpy atteint plusieurs GFLOPS, et son débit augmente avec n.

2-3. Code et exécution

Premier lancement : téléchargement de Python (Pyodide) et numpy, ~10-20 s.
4. Ce qu'il faut observer
Les GFLOPS de numpy augmentent avec la taille : l'intensité arithmétique (calcul par octet) croît.
5. Interprétation
Un produit n×n fait 2n³ opérations sur 3n² nombres : plus n est grand, plus chaque nombre chargé est réutilisé, et moins la mémoire limite. Les bibliothèques BLAS découpent la matrice en blocs qui tiennent dans le cache.
6. Lien avec le HPC
C'est exactement le calcul qu'accélèrent les Tensor Cores des H100 de Jean Zay, à des débits de l'ordre de centaines de TFLOPS en précision réduite.

Expérience 4

Un neurone apprend la fonction OU

1. Objectif
Écrire la boucle d'entraînement complète, sans bibliothèque.
Résultat attendu
La perte diminue régulièrement et les prédictions s'approchent de 0, 1, 1, 1.

2-3. Code et exécution

Premier lancement : téléchargement de Python (Pyodide) et numpy, ~10-20 s.
4. Ce qu'il faut observer
Remplace les données par XOR (0,1,1,0) : la perte stagne. Pourquoi ?
5. Interprétation
Forward, perte, gradient, mise à jour : c'est la boucle de tout entraînement d'IA. Avec un seul neurone, la frontière est une droite, insuffisante pour XOR.
6. Lien avec le HPC
Un grand modèle exécute la même boucle avec des milliards de poids, en produits de matrices sur des centaines de GPU qui moyennent leurs gradients à chaque étape.

Expérience 5

Multiprocessing : utiliser tous ses cœurs (à lancer sur ta machine)

1. Objectif
Mesurer l'accélération réelle avec 1, 2, 4… processus et la comparer à l'idéal.
Résultat attendu
L'accélération augmente avec le nombre de processus mais reste sous l'idéal, puis plafonne au nombre de cœurs physiques.

2-3. Code et exécution

À copier et exécuter sur ta machine (python3 fichier.py).
4. Ce qu'il faut observer
L'écart entre accélération mesurée et idéale ; le coût fixe de création des processus.
5. Interprétation
Créer des processus et rassembler les résultats a un coût fixe (partie séquentielle). Au-delà du nombre de cœurs, les processus se partagent les mêmes unités.
6. Lien avec le HPC
Sur un nœud H100 de Jean Zay (96 cœurs), on fait la même expérience à plus grande échelle ; entre nœuds, on utilise MPI, et la communication s'ajoute au coût.
